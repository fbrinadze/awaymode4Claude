# Away Mode v1.3.0 (vacation mode) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Vacation mode: away for days, check-ins at the user's times, approvals answerable from Teams for the whole trip, and the PC kept awake.

**Architecture:** Vacation is a flag on an away project (`ProjectState.vacation`), so routing, commands and the recap are reused. Pure helpers (check-in schedule, day/weekday times) live in small new files; the owner server's existing 5-second inbox timer sends check-ins and holds/releases a keep-awake request.

**Tech Stack:** Bun + TypeScript (strict), `bun:ffi` (built in) for Windows power calls, `caffeinate` / `systemd-inhibit` child processes on macOS/Linux, PowerShell 5.1 installer.

**Spec:** `docs/superpowers/specs/2026-11-27-v1.3.0-vacation-design.md`

## Global Constraints

- Zero runtime dependencies (Bun built-ins allowed); no inbound listener; files ≤150 lines, functions ≤40; test-first with fakes, RED seen before GREEN.
- Nothing approves except the user's `yes <id>`; `never_relay`, `more`, secrets and the sender gate unchanged.
- Vacation and plain away periods are capped at 30 days (`MAX_AWAY_MS = 30 * 24 * 3_600_000`).
- `vacation_checkins` default `9:00`; `vacation_return_time` default `9:00`; both in plugin.json `userConfig` and `mcpServers.away.env` (`AWAY_VACATION_CHECKINS`, `AWAY_VACATION_RETURN_TIME`).
- Keep-awake is held only while this server owns at least one project on vacation, and released on every end path and on process exit.
- Check-in card: kind `checkin`, subtitle "Check-in"; idle text exactly "Still working. Nothing needs you."
- `install.ps1` stays PowerShell 5.1, CRLF, each .ps1 ≤150 lines.
- Version `1.3.0` only in Task 8. Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push to main, never merge.

## Review Focus

1. A long PC sleep across several check-in times: exactly one catch-up check-in, not one per missed time → Task 5.
2. Two servers own different projects and one ends vacation: keep-awake stays held while any owned project is still on vacation; released when the last ends → Task 6.
3. Typing at the terminal on vacation (hook sets `awayUntil = 0`): vacation ends and keep-awake is released on the owner's next tick → Task 6.
4. A check-in time just after midnight (`0:30`) and times given unordered (`18:00,8:00`): due times computed on local calendar days, in order → Task 3.
5. `vacation_checkins` garbage (`25:00, x, `): falls back to `9:00`, no crash → Task 3.

### Task 1: Vacation state, lifecycle and the 30-day ceiling

**Files:** Modify `plugin/server/store.ts` (field + validation), `plugin/server/recap.ts` (`startAway`, `endAway`, `beginAway`), `plugin/server/tools.ts` (`set_away`, `statusText`), `plugin/skills/away/SKILL.md`. Test: `test/vacation.test.ts`.

**Interfaces — Produces:**
- `ProjectState.vacation?: { since: number; lastCheckinAt: number; finished: number }` — present = on vacation. Validated in `store.ts` (numbers via `num`; anything else → `undefined`).
- `export const MAX_AWAY_MS = 30 * 24 * 3_600_000` in `plugin/server/when.ts`.
- `beginAway(l: Life, tag: string, until: number, vacation?: boolean): string[]`; `startAway(s, key, until, now, instance, vacation?: boolean)` sets `vacation = { since: now, lastCheckinAt: now, finished: 0 }` when true; `endAway` clears it.
- `set_away` input adds `vacation: boolean`, `days: number`; `days` → `now + days * 86_400_000`. Any end > `now + MAX_AWAY_MS` throws `"Away mode can last at most 30 days."`.
- `statusText`: `On vacation until <clock>` when `vacation` is set, else unchanged.

**Interfaces — Produces:**

### Task 3: Check-in schedule and text (pure)

**Files:** Create `plugin/server/checkin.ts`. Test: `test/checkin.test.ts`.

**Interfaces — Produces:**
- `parseCheckins(s: string | undefined): { h: number; m: number }[]` — comma-separated `H:MM` / `H` / `Ham|pm`; invalid entries dropped; none valid → `[{h:9,m:0}]`; sorted.
- `dueCheckin(times, lastAt: number, now: number): number | null` — the latest scheduled local time `t` with `lastAt < t <= now` (look back at most 2 days), else null. One value even if several passed.
- `checkinText(p: ProjectState, now: number): string` — lines: `On vacation until <clock(p.awayUntil, now)>`; `<n> finished since the last check-in (sent as they happened)` if `vacation.finished > 0`; `Waiting for you:` with each permission `- <tool> <id> (waiting <Xh>): reply yes <id> or no <id>` and each question `- <id>: <text> (waiting <Xh>)`; `Parked:` with `recap` parked texts and the line `Reply with what to do and it goes to Claude.`; or exactly `Still working. Nothing needs you.` when there are no permissions, questions, parked items or finished count.
- [ ] **Step 1: Failing tests**: `9:00 default`; `garbage falls back to 9:00` (Review Focus 5); `unordered times are sorted`; `0:30 just after midnight is due once` (Review Focus 4); `several missed times give one due time` (Review Focus 1); `nothing due before the first time`; `checkinText lists approvals with ids and reply line`; `idle text`.
- [ ] **Steps 2–5:** RED → implement → green → commit `feat: check-in schedule and text`.

### Task 6: Keep the PC awake

**Files:** Create `plugin/server/keepawake.ts`. Modify `plugin/server/away.ts` (or `inbox-loop.ts`): each tick `want = this instance owns a project on vacation`; hold/release on change; release on `process.on("exit")`. Laptop note on vacation start. Test: `test/keepawake.test.ts`.

**Interfaces — Produces:**
- `export interface KeepAwake { hold(display: boolean): void; release(): void; held(): boolean }`
- `export function isLaptop(platform = process.platform): boolean` (Windows `GetSystemPowerStatus` `BatteryFlag !== 128`; macOS `pmset -g batt` contains `InternalBattery`; Linux any `/sys/class/power_supply/BAT*`).
- `export function keepAwake(platform = process.platform): KeepAwake` — Windows `bun:ffi` `SetThreadExecutionState(0x80000001 | (display ? 0x00000002 : 0))` / `0x80000000`; macOS child `caffeinate -i [-d] -w <pid>`; Linux child `systemd-inhibit --what=sleep --why="Away Mode vacation" sleep infinity`, or a no-op that reports `held() === false` if the binary is missing.
- `Deps.keepAwake?: KeepAwake` (tests inject a fake).
- Vacation start on a laptop sends once: `"On a laptop: keep the lid open, or set 'When I close the lid: Do nothing' while plugged in."`
- [ ] **Step 1: Failing tests** (fake KeepAwake): `held while on vacation`; `released on back`, `on expiry`, `on terminal input` (Review Focus 3), `on handover`; `two projects: released only when the last vacation ends` (Review Focus 2); `plain away never holds`; `laptop note sent once`.
- [ ] **Steps 2–5:** RED → implement → green → commit `feat: keep the PC awake on vacation`.
