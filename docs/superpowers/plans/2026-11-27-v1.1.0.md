# Away Mode v1.1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Several Claude Code sessions can be away at once, with Teams replies routed to the right project; the run-2 lifecycle gaps are closed; five new Teams commands and checks ship; and the plugin is ready for Anthropic's directory.

**Architecture:** `state.json` becomes a v2 store: shared fields plus a `projects` map keyed by project path, written only under a lock. One server holds a poll lease, dispatches each Teams message to a project's inbox, and each project's owner instance delivers its own inbox. The existing per-project logic (route, relay, tools) keeps working on a per-project view, so the v1.0.1 security behaviour is unchanged.

**Tech Stack:** Bun (TypeScript, no build step), `bun:test`, plain `fetch`, `node:fs`. Zero runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-11-27-v1.1.0-design.md` (read it first; section numbers below refer to it).

## Global Constraints

- Zero runtime dependencies; no MSAL, Bot Framework or MCP SDK.
- No file over 150 lines and no function over 40 (`bun run check` doesn't enforce this; check with `wc -l`).
- Microsoft scopes stay exactly `User.Read`, `Chat.Read`, `TeamsAppInstallation.ReadWriteSelfForUser` (+ `offline_access`).
- Sender gate on `msg.from === store.me` runs before any parsing.
- Hooks import nothing from the project and do nothing when no project is away.
- `state.json` is always written with mode `0o600` through a temp file and rename, under `state.lock`.
- A new setting goes in both `plugin.json` userConfig and the `AWAY_*` env map in `plugin.json` `mcpServers.away.env`.
- Every task ships with fake-adapter tests; requirements R1–R4 and every bug-shaped item get a test that fails first.
- v1.0.1 rules stay: `yes|no <id>`, the strict bare-verdict rule, one approval per call, `never_relay` terminal-only, previews over 600 characters terminal-only unless `more` sent them in full.
- Release version: `1.1.0` in `plugin/.claude-plugin/plugin.json`, set in the last PR only.
- Write the code fully. Never leave `TODO(human)` or hand code back to the user.
- Run tests with Bun on PATH. On this machine: `export PATH="/c/Users/fbrinadze/AppData/Local/Microsoft/WinGet/Packages/Oven-sh.Bun_Microsoft.Winget.Source_8wekyb3d8bbwe/bun-windows-x64:$PATH"`.

## Review Focus

1. **Server restart while away.** A restarted server gets a new instance token. If the project's owner has gone silent (no heartbeat for 2 × `MAX_DELAY`), the restarted server in that project adopts ownership and its pending permissions. Test in Task 6.
2. **Project folder renamed or deleted while away.** Its entry never expires on its own, so `loadStore` prunes non-away project entries with no pending items, and away entries expire normally. Test in Task 1.
3. **`until 6pm` after 6pm.** `extend`/`until` reuse `resolveUntil` semantics (the next occurrence). A past time returns "That time has passed" and changes nothing. Test in Task 9.
4. **`@a yes <id that belongs to b>`.** The tag wins and nothing is approved. The reply is "abcde is waiting in b, not a." Test in Task 4.
5. **A crashed process leaves `state.lock` behind.** A lock older than 5 s is removed and the write proceeds. A fresh lock makes the writer retry for up to 2 s, then throw `StateBusy`. Test in Task 1.

  - `"writes are 0600 and atomic"`: after `withStore(dir, T, s => { s.me = "u" })`, `statSync(file).mode & 0o777` is `0o600` (skip on win32), no `*.tmp` remains, and no `state.lock` remains.
  - `"a stale lock is removed"`: create `state.lock` with mtime `T - 6_000`; `withStore` succeeds.
  - `"a fresh lock is waited for, then reported"`: create `state.lock` now; `withStore` throws `StateBusy` after about 2 s (allow 1.5–3 s).
